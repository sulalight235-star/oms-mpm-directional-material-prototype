# 奖励管理列表操作字段调整设计

## 目标

调整 `MPM-咸亨产品奖励管理-奖励配置列表.html` 的筛选条件和列表字段口径：
- 筛选区新增 `操作人`
- 筛选区新增 `操作时间`，采用按日的起止范围筛选
- 列表中的 `更新时间`、`更新人` 统一改为 `操作时间`、`操作人`
- 页面内相关导出字段和说明文案同步统一口径

## 现状

当前页面已支持以下筛选项：
- 物料编码
- 物料名称
- 奖励类型
- 配置状态
- 奖励有效期

当前列表表头仍为：
- 更新时间
- 更新人

当前导出字段和说明文案中仍存在：
- 最近更新时间
- 最近更新人

## 方案

采用统一口径方案：

1. 视觉层
- 在筛选区增加 `操作人` 输入框
- 在筛选区增加 `操作时间` 日期范围，使用两个 `date` 输入框承载开始和结束日期
- 保持现有原型风格，不引入新的复杂交互控件

2. 数据层
- 继续复用现有 mock 数据字段 `updated`、`updater`
- 仅在展示文案层统一改名为 `操作时间`、`操作人`
- 操作时间筛选按 `updated` 的日期部分参与比较，粒度为 `yyyy-MM-dd`

3. 交互层
- `操作人` 使用模糊匹配
- `操作时间` 支持三种情况：
  - 仅开始日期
  - 仅结束日期
  - 开始日期和结束日期同时存在
- 日期范围为闭区间，包含起止当天

4. 一致性层
- 列表表头统一为 `操作时间`、`操作人`
- 奖励规则导出表头统一为 `操作人`、`操作时间`
- 奖励规则导出说明中的系统列说明同步改为 `操作人`、`操作时间`
- 页面提示文案中补充新筛选项说明

## 边界与取舍

- 本次只改当前原型页，不扩散到其他 HTML 页面
- 不引入日期时间级别筛选，避免增加原型复杂度
- 不重构现有 mock 数据结构，避免无收益的大范围改动

## 验收标准

- 页面存在 `操作人` 筛选项
- 页面存在 `操作时间` 起止日期筛选项
- 列表表头不再出现 `更新时间`、`更新人`
- 列表表头出现 `操作时间`、`操作人`
- 查询逻辑同时支持 `操作人` 模糊筛选和 `操作时间` 日期范围筛选
- 导出字段与说明文案不再出现 `最近更新时间`、`最近更新人`
